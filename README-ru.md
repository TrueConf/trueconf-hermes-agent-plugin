> Данный плагин является gateway-интерфейсом для взаимодействия с Hermes Agent. TrueConf не призывает к использованию Hermes Agent, не рекомендует его внедрение в корпоративной инфраструктуре и не несёт ответственности за работу Hermes Agent, связанных ИИ-агентов, внешних сервисов или сторонних компонентов.
>
> Использование плагина и подключение к Hermes Agent выполняются пользователем самостоятельно и на собственный риск. Перед развертыванием в корпоративной сети необходимо ознакомиться с рисками информационной безопасности, включая утечку данных, несанкционированный доступ, prompt injection, выполнение нежелательных команд, компрометацию API-ключей и непредвиденное поведение ИИ-агентов:
>

>
> Рекомендуется использовать данный плагин только после оценки рисков, тестирования в изолированной среде, ограничения прав доступа, настройки мониторинга и принятия мер для защиты корпоративной инфраструктуры.

Плагин TrueConf позволяет общаться с Hermes Agent прямо из TrueConf: задавать
вопросы в личном чате, подключать агента к рабочим группам и получать результаты
задач по расписанию. Он поддерживает текст, изображения, файловые вложения
и голосовые сообщения. При включённом распознавании речи Hermes преобразует
голосовые сообщения в текст с помощью локального `faster-whisper`.[^voice]

Это руководство описывает установку и настройку **плагина 1.0.0**. Плагин
предназначен для **Hermes Agent v0.21.0**; совместимость с другими версиями
Hermes пока не проверена.

## Перед началом

Понадобятся:

- Установленный и настроенный Hermes Agent v0.21.0. Убедитесь, что он уже
  отвечает на запросы в терминале: плагин подключает TrueConf к существующему агенту.
- TrueConf Server, доступный с компьютера или сервера, где работает Hermes.
- Отдельная учётная запись TrueConf для бота и её пароль. Если у вас нет права
  создавать учётные записи, попросите администратора TrueConf подготовить её.
- Адрес TrueConf Server, например `video.example.com`.
- Точный идентификатор вашего пользователя TrueConf — он потребуется для
  разрешения доступа. Это идентификатор учётной записи, а не отображаемое имя.
- Git на компьютере с Hermes: он нужен для установки плагина из репозитория.

> [!NOTE]
> Команды из этого руководства выполняются в терминале на компьютере с Hermes.
> Не отправляйте их боту в TrueConf.

Связь с TrueConf обеспечивает библиотека `python-trueconf-bot` версии
`>=1.5.0,<2`. Обычно Hermes устанавливает нужные зависимости автоматически
при запуске шлюза.[^dependencies]

## Установка и первый запуск

### 1. Установите плагин

```bash
hermes plugins install https://github.com/TrueConf/trueconf-hermes-agent-plugin.git --enable
```

Установщик запросит параметры подключения:

| Параметр | Что указать |
|---|---|
| `TRUECONF_SERVER` | Имя или IP-адрес сервера, например `video.example.com`, без `https://` и без пути. |
| `TRUECONF_USERNAME` | Имя учётной записи бота. |
| `TRUECONF_PASSWORD` | Пароль бота. При вводе он скрыт. |
| `TRUECONF_VERIFY_SSL` | `true` — проверять сертификат сервера; это рекомендуемый вариант.[^tls] |

> [!CAUTION]
> Пароль сохраняется в файле секретных переменных окружения профиля Hermes,
> обычно `~/.hermes/.env`. Не записывайте его в `config.yaml`, команды терминала
> или файлы репозитория.

### 2. Настройте доступ через мастер

```bash
hermes gateway setup
```

Выберите **TrueConf**. Мастер покажет сохранённые параметры подключения и
позволит настроить проверку сертификата, доступ пользователей и основной чат
для уведомлений. Если он предложит повторную настройку TrueConf, согласитесь.

Для первого запуска:

1. Проверьте адрес сервера и учётную запись бота.
2. Оставьте проверку сертификата включённой.
3. На вопрос о доступе для всех пользователей ответьте **нет**.
4. Введите свой точный идентификатор TrueConf в список разрешённых пользователей.
   Несколько идентификаторов разделяйте запятыми; сохраняйте их регистр.
5. Основной чат можно пока не указывать и настроить позже.

> [!IMPORTANT]
> Мастер сохраняет настройки в активном профиле Hermes. Если вы используете
> именованный профиль, выполняйте все команды с ним.[^profiles]

### 3. Запустите шлюз

Шлюз — процесс Hermes, который получает сообщения из TrueConf и доставляет
ответы агента. Он должен работать всё время, пока вы пользуетесь ботом.

```bash
hermes gateway restart
hermes gateway status
```

После запуска проверьте плагин:

```bash
hermes plugins doctor trueconf-platform --ci
```

Если проверка сообщает об отсутствующих зависимостях, откройте раздел
[«Если что-то не работает»](#если-что-то-не-работает).

### 4. Отправьте первое сообщение

Откройте личный чат с учётной записью бота в TrueConf и отправьте, например:
«Привет! Чем ты можешь мне помочь?».

Если бот ответил, подключение работает. Теперь можно добавить его в группу
или настроить доставку результатов задач по расписанию.

## Как общаться с агентом

**В личном чате** пишите боту обычные сообщения. Упоминание не требуется.

**В группе или канале** по умолчанию нужно упомянуть бота средствами TrueConf.
Выберите его в интерфейсе упоминаний: простое написание имени в тексте
не заменяет упоминание. Доступ к агенту также должен быть разрешён в настройках.

Когда Hermes уточняет вопрос или просит подтвердить действие:

- В личном чате выберите кнопку под сообщением.
- В группе или канале ответьте номером предложенного варианта.
- Если Hermes предлагает ввести ответ текстом, следуйте инструкции в сообщении.

В группах используются текстовые ответы, чтобы можно было проверить,
кто именно подтвердил действие.[^buttons]

Длинные ответы приходят несколькими сообщениями. По умолчанию первый ответ
привязан к вашему запросу, а продолжения образуют цепочку. Это поведение
можно изменить настройкой `reply_to_mode`.[^replies]

## Кому разрешён доступ

Бот получает доступ к возможностям вашего Hermes, поэтому разрешайте работу
с ним только нужным людям. По умолчанию неизвестному отправителю доступ
закрыт. Если список пользователей пуст, требуется одобрить привязку пользователя
(pairing) в Hermes или явно настроить доступ.

Для простого сценария используйте список пользователей в мастере настройки.
Он сохраняется как `TRUECONF_ALLOWED_USERS` и действует в личных чатах,
группах и каналах.

Для раздельных правил используйте `~/.hermes/config.yaml`:

```yaml
platforms:
  trueconf:
    # Кто может писать агенту в личных чатах.
    allow_from:
      - alice@example.com

    # Кто может вызывать агента в группах и каналах.
    group_allow_from:
      - moderator@example.com
```

Замените значения примера точными идентификаторами пользователей TrueConf.

> [!TIP]
> Если в файле уже есть блоки `platforms:` и `trueconf:`, добавьте параметры
> в существующий блок. Не создавайте второй блок с тем же именем; сохраняйте
> отступы пробелами.

Выберите один источник списков: мастер с `TRUECONF_ALLOWED_USERS` либо YAML.
При переходе на YAML удалите `TRUECONF_ALLOWED_USERS` из файла `.env`
активного профиля, чтобы он не переопределял выбранные правила.

> [!WARNING]
> `TRUECONF_ALLOW_ALL_USERS=true` открывает доступ всем пользователям TrueConf,
> которые могут обратиться к боту, и имеет приоритет над списками. Для личного
> или рабочего агента оставляйте эту возможность выключенной.

После изменения доступа перезапустите шлюз:

```bash
hermes gateway restart
```

## Работа в группах и каналах

Здесь используются идентификаторы чатов TrueConf (`chat_id`), а не названия
групп. Получите нужный идентификатор из данных TrueConf или попросите
администратора помочь. Значения `agent-room-id` и `team-chat-id` ниже — примеры:
их нужно заменить реальными идентификаторами.

Примеры предполагают настройку доступа через YAML. Если доступ ранее задавался
в мастере, сначала согласуйте источники настроек, как описано в разделе
[«Кому разрешён доступ»](#кому-разрешён-доступ).

### Отдельный чат для общения с агентом

В чате, созданном специально для агента, можно разрешить всем участникам
обращаться к нему без упоминания:

```yaml
platforms:
  trueconf:
    allowed_chats:
      - agent-room-id
    group_allowed_chats:
      - agent-room-id
    require_mention: true
    free_response_chats:
      - agent-room-id
```

Каждое поддерживаемое сообщение участника в этом чате вызывает агента.
В остальных группах и каналах требование упоминания сохраняется.

### Рабочая группа: отвечать по упоминанию и учитывать разговор

Чтобы агент отвечал только по обращению, но мог учитывать недавние сообщения
группы, используйте:

```yaml
platforms:
  trueconf:
    allowed_chats:
      - team-chat-id
    group_allowed_chats:
      - team-chat-id
    require_mention: true
    observe_unmentioned_group_messages: true
    observe_context_limit: 20
```

Обычные сообщения не вызывают ответа. Когда участник упоминает агента,
тот получает до 20 подходящих предшествующих записей, начиная после
предыдущего обращения. История запрашивается в момент обращения;
плагин не ведёт отдельный архив фонового разговора.[^context]

В этом примере доступ есть у всех участников `team-chat-id`. Чтобы разрешить
его только выбранным людям, уберите `group_allowed_chats` и добавьте их
идентификаторы в `group_allow_from`.

### Что означают параметры

| Параметр | Назначение |
|---|---|
| `allowed_chats` | Ограничивает работу агента перечисленными группами и каналами. Сам по себе не разрешает доступ их участникам. |
| `group_allowed_chats` | Разрешает доступ всем участникам перечисленных групп и каналов. |
| `group_allow_from` | Разрешает доступ отдельным пользователям в группах и каналах. |
| `require_mention` | При `true` агент отвечает только на упоминание. По умолчанию `true`; личные чаты не затрагиваются. |
| `free_response_chats` | Отменяет требование упоминания в отдельных чатах. Сам по себе не предоставляет доступ. |
| `observe_unmentioned_group_messages` | Позволяет учитывать сообщения без обращения как контекст следующего запроса. |
| `observe_context_limit` | Число проверяемых предшествующих записей: по умолчанию `20`, от `0` до `100`. `0` отключает получение контекста. |

Непустой `allowed_chats` исключает все неуказанные группы и каналы.
В разрешённом чате доступ должен дополнительно предоставляться через
`group_allowed_chats` или `group_allow_from`.

Глобальное `require_mention: false` снимает требование упоминания во всех
группах и каналах с разрешённым доступом. Если это нужно только одному чату,
используйте `free_response_chats`.

## Уведомления и задачи по расписанию

Основной чат (`home_channel`) — место, куда Hermes может доставлять уведомления
и результаты задач по расписанию (cron). Это может быть существующий личный
чат, группа или канал.

Его идентификатор можно задать в мастере настройки или в `.env` активного профиля:

```dotenv
TRUECONF_HOME_CHANNEL=Exact-Case-Sensitive-Chat-ID
```

Замените пример реальным `chat_id`, сохранив регистр и убрав пробелы по краям.
Идентификатор чата отличается от идентификатора пользователя.

Также можно задать основной чат в YAML:

```yaml
platforms:
  trueconf:
    home_channel:
      platform: trueconf
      chat_id: Exact-Case-Sensitive-Chat-ID
      name: Уведомления Hermes
```

`TRUECONF_HOME_CHANNEL` имеет приоритет над YAML и используется Hermes
для автономной доставки задач cron, когда активное подключение шлюза
не используется. Для этого сценария задайте переменную окружения.

После настройки проверьте доставку обычной задачей Hermes по расписанию.
Текст с вложениями поддерживается; для отправки только вложения есть
ограничение Hermes v0.21.0, описанное ниже.

## Настройки подключения

Для первого запуска достаточно мастера. YAML нужен, если вы хотите изменить
порт, использовать собственный сертификат или подробнее настроить поведение.
Учётные данные при этом остаются в `.env` профиля.

```yaml
plugins:
  enabled:
    - trueconf-platform

platforms:
  trueconf:
    enabled: true
    server: video.example.com
    port: 443
    https: true
    verify_ssl: true
    parse_mode: html
    require_mention: true
```

Сохраните другие включённые плагины в списке `plugins.enabled` и остальные
настройки вашего файла. Если имя сервера уже задано установщиком или мастером,
`TRUECONF_SERVER` имеет приоритет над YAML-параметром `server`.

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `port` | `443` | Порт TrueConf Server. |
| `https` | `true` | Использовать защищённое соединение. |
| `verify_ssl` | `true` | Проверять сертификат; также принимает путь к файлу сертификатов CA.[^tls] |
| `parse_mode` | `html` | Единственный поддерживаемый режим передачи форматированного текста. |
| `reply_to_mode` | `first` | Привязка ответов к исходному сообщению: `first`, `all` или `off`.[^replies] |

При наличии непустых `TRUECONF_SERVER`, `TRUECONF_USERNAME` и
`TRUECONF_PASSWORD` платформа может включаться без блока `trueconf:` в YAML.
Блок нужен для дополнительных настроек поведения. Явное `enabled: false`
отключает платформу.

### Если сервер использует сертификат вашей организации

Попросите администратора предоставить файл сертификатов центров сертификации
(CA bundle) и укажите доступный для чтения путь на компьютере с Hermes:

```yaml
platforms:
  trueconf:
    verify_ssl: /etc/company-pki/trueconf-ca.pem
```

Значение `TRUECONF_VERIFY_SSL`, введённое при установке, задаёт начальную
настройку проверки; последующие изменения можно вносить явно в YAML.

> [!CAUTION]
> Не используйте `verify_ssl: false` как постоянное решение ошибки сертификата.
> Оно отключает проверку подлинности сервера и допускает перехват пароля и
> сообщений. Этот вариант предназначен только для кратковременного тестирования
> в контролируемой среде; плагин выводит предупреждение при его использовании.

## Возможности и ограничения

Плагин 1.0.0 поддерживает:

- Личные чаты, группы и каналы TrueConf.
- Текстовые сообщения и ответы с привязкой к исходному сообщению.
- Документы, изображения, видео, голосовые сообщения и аудиофайлы на входе
  и выходе; изображения отображаются с предпросмотром.
- Расшифровку входящих голосовых сообщений через локальный `faster-whisper`,
  если в Hermes включено и настроено распознавание речи.[^voice]
- Форматирование ответов: жирный текст, курсив, подчёркивание, зачёркивание,
  ссылки, списки, цитаты и таблицы.[^formatting]
- Кнопки уточнения и подтверждения в личных чатах; выбор номером в группах.
- Доставку результатов задач по расписанию, в том числе текста с вложениями.
- Обновление сообщений о ходе работы вместо постоянной отправки новых
  сообщений с тем же статусом.

Ограничения, которые следует учитывать:

| Ограничение | Что это означает |
|---|---|
| Проверена только Hermes v0.21.0 | Работа с другими версиями Hermes не гарантируется. |
| SDK `>=1.5.0,<2` | Более ранние версии `python-trueconf-bot` и ветка 2.x не поддерживаются. |
| Исходящие видео и голосовые сообщения | Доставляются как файловые вложения, а не как специальные видео- или голосовые сообщения TrueConf. |
| Не более 4096 видимых символов в сообщении | Длинные ответы автоматически разбиваются на цепочку. Подписи к вложениям не разбиваются. |
| Отправка только медиа без текста | Hermes v0.21.0 отклоняет её до вызова стороннего автономного отправителя. Сам обработчик плагина такую доставку поддерживает. |
| Входящие вложения: по умолчанию до 128 МиБ | Лимит задаёт `gateway.max_inbound_media_bytes`; `0` отключает ограничение. Увеличение повышает потребление памяти. |
| Стикеры | Исходящие WebP отправляются через API стикеров; входящие поступают как обычные вложения. |
| «Избранное», ветки и темы | Не поддерживаются как адресаты. |
| Редактирование длинного ответа | Если ранее разбитый ответ становится короче, прежние части могут остаться в чате.[^edits] |

## Если что-то не работает

Сначала проверьте состояние шлюза и последние записи журнала:

```bash
hermes gateway status
hermes logs gateway -n 100
```

| Проблема | Что сделать |
|---|---|
| Бот не отвечает в личном чате | Убедитесь, что шлюз работает, плагин включён и ваш точный ID разрешён. Проверьте активный профиль Hermes. |
| Платформа отключена | Проверьте наличие `trueconf-platform` в `plugins.enabled`, отсутствие `enabled: false` и заполненные сервер, имя бота и пароль. |
| TrueConf недоступен или не хватает зависимостей | После запуска шлюза выполните `hermes plugins doctor trueconf-platform --ci`. Если автоматическая установка не сработала, используйте команды ниже. |
| Ошибка входа | Проверьте учётную запись и пароль бота. Убедитесь, что другой шлюз не использует ту же учётную запись на том же сервере. |
| Ошибка сертификата | Укажите правильный файл сертификатов CA; обратитесь к администратору сервера. |
| Личный чат работает, группа — нет | Проверьте доступ пользователя или всей группы, список `allowed_chats` и упоминание бота средствами TrueConf. |
| Правила YAML не действуют | Проверьте, не заданы ли `TRUECONF_ALLOWED_USERS` или `TRUECONF_ALLOW_ALL_USERS` в `.env` профиля. |
| Агент не учитывает разговор группы | Чат должен быть явно указан в `allowed_chats`, отсутствовать в `free_response_chats`, а `require_mention` и `observe_unmentioned_group_messages` должны быть `true`. |
| Уведомления не приходят | Проверьте существующий `chat_id` в `TRUECONF_HOME_CHANNEL`, регистр и отсутствие пробелов по краям. |
| Большое вложение отклоняется | Проверьте `gateway.max_inbound_media_bytes`. Оцените доступную память перед увеличением лимита. |
| Соединение постоянно обрывается | Проверьте доступность сервера и ошибки исчерпания повторных попыток SDK в журнале шлюза. |

### Ручная установка зависимостей

Запустите эту команду **в том же окружении Python, в котором работает Hermes**:

```bash
python -m pip install "mistune>=3,<4" "python-trueconf-bot>=1.5.0,<2"
```

Если Hermes установлен через `uv tool`, добавьте зависимости в его окружение:

```bash
uv tool inject hermes-agent "mistune>=3,<4" "python-trueconf-bot>=1.5.0,<2"
```

После установки перезапустите шлюз и повторите проверку плагина. Установка
пакетов в другой системный Python не исправит окружение Hermes.

### Где посмотреть подробности

```bash
hermes plugins list
hermes status
hermes logs errors
hermes logs -f
```

`hermes logs -f` показывает вывод в реальном времени; остановите просмотр
сочетанием `Ctrl+C`. Журналы обычно находятся в `~/.hermes/logs/`.

> [!WARNING]
> Перед передачей журналов другим людям удалите пароли, имена серверов,
> идентификаторы пользователей, содержимое сообщений и параметры URL.

Для сообщения о проблеме используйте
[Issues репозитория](https://github.com/TrueConf/trueconf-hermes-agent-plugin/issues).
Укажите версии Hermes и плагина, ожидаемое поведение и текст ошибки.

## Переход с прежней интеграции

Если вы уже использовали другой адаптер TrueConf для Hermes:

1. Остановите шлюз и сделайте резервную копию активного профиля.
2. Удалите прежнюю интеграцию по её документации. Если она изменяла ядро Hermes,
   используйте чистую установку Hermes v0.21.0.
3. Удалите прежние `lib_patches`, переопределения SDK, обработчики патчей после
   обновлений и изменения путей Python для старого адаптера.
4. Установите этот плагин и перенесите сервер, учётные данные, список доступа
   и идентификатор основного чата.
5. Перенесите порт, транспорт, режим разметки и требование упоминания в
   `platforms.trueconf`. `TRUECONF_USE_SSL` и другие прежние переменные
   не поддерживаются; `TRUECONF_VERIFY_SSL` поддерживается при установке.
6. Проверьте права доступа и проверку сертификата перед запуском.
7. Выполните проверку первого запуска, оставив прежнюю интеграцию остановленной.

Прежнее преобразование HTML, автоматическое определение основного чата,
собственные ограничения частоты запросов и циклы переподключения старого
плагина, а также патчи ядра Hermes не переносятся.

## Отключение и удаление

Чтобы отключить плагин, сохранив его файлы и настройки:

```bash
hermes plugins disable trueconf-platform
hermes gateway restart
```

Чтобы удалить установленный плагин:

```bash
hermes gateway stop
hermes plugins remove trueconf-platform
```

Удаление плагина сохраняет настройки и секреты профиля. Если они больше
не нужны другим процессам, удалите блок `trueconf` из `config.yaml` и записи
`TRUECONF_*` из `.env` выбранного профиля. Затем запустите шлюз снова, если
он нужен для других подключений.

## Для разработчиков

Плагин использует публичные API Hermes и `python-trueconf-bot`. Установка
не требует изменения ядра Hermes или включения копии SDK в состав плагина.

Тесты не требуют подключения к TrueConf Server:

```bash
pytest tests -q
ruff check .
ty check
```

Архитектура и принятые решения описаны в [CONTEXT.md](CONTEXT.md).
Исходная [спецификация поведения](docs/specs/0001-observable-behavior.md)
и [план реализации](docs/plans/0001-first-implementation.md) относятся
к этапу 0.1.0; последующие изменения зафиксированы в
[дополнениях к спецификации](docs/specs/0004-observable-behavior-amendments.md).
Для пользовательской настройки выпуска 1.0.0 используйте это руководство.

[^dependencies]: Автоматическая установка зависит от настройки Hermes `security.allow_lazy_installs`. Плагин проверяет версии SDK и Mistune при запуске платформы и при необходимости вызывает установку в окружение шлюза. Если установка запрещена или завершилась ошибкой, зависимости нужно установить вручную. Поле `python_dependencies` в манифесте само по себе пакеты не устанавливает.

[^tls]: TLS защищает соединение; проверка сертификата подтверждает, что подключение установлено с нужным сервером. При установке `TRUECONF_VERIFY_SSL` принимает `true`, `false` или путь к доступному для чтения файлу сертификатов CA. Для частной PKI используйте файл её CA, сохраняя проверку включённой.

[^profiles]: Профиль — отдельный набор настроек Hermes. Для профиля `work` добавляйте `-p work` перед подкомандой, например `hermes -p work gateway setup` и `hermes -p work gateway restart`. Установку плагина и последующие действия выполняйте с одним профилем; пути `~/.hermes/config.yaml` и `~/.hermes/.env` в руководстве относятся к обычному профилю.

[^buttons]: Событие TrueConf `CallbackQuery` не сообщает, кто нажал кнопку. Текстовый ответ позволяет проверить отправителя обычным механизмом авторизации Hermes. Текст также используется для открытых вопросов, слишком большого числа вариантов или при ошибке отправки кнопок.

[^replies]: `first` привязывает первое доставленное сообщение к запросу, а продолжения — к предыдущей части; `all` привязывает каждую часть к запросу; `off` отключает привязку. Допустимы только эти три значения.

[^context]: Получение фонового контекста работает только при `require_mention: true`, явном наличии чата в `allowed_chats` и отсутствии в `free_response_chats`. Исключаются сообщения агента, предыдущие упоминания этого агента (включая `@all`), нетекстовые и пустые сообщения, а также сообщения без разрешённого доступа. Предыдущее разрешённое упоминание ограничивает окно истории. Упоминания других пользователей и поддерживаемый HTML сохраняются. Лимиты — 1 000 символов на сообщение и 12 000 на блок; при переполнении первыми удаляются старые сообщения. Ошибка получения истории не блокирует ответ на запрос. В личных чатах этот механизм не применяется.

[^formatting]: Агент пишет Markdown, а плагин преобразует его в HTML TrueConf с тегами `<b>`, `<i>`, `<s>`, `<u>`, `<a>` и `<br>`. Фрагменты кода отображаются выделенным текстом, заголовки — жирным, цитаты — курсивом в кавычках; широкие таблицы преобразуются в блоки «поле: значение». Спойлеры заменяются на `[spoiler]`. Неподдерживаемая разметка сохраняется как читаемый текст; ссылки с небезопасной схемой не превращаются в активные ссылки. Исходный HTML передаётся для очистки серверу, а небезопасные или неполные теги ссылок предварительно превращаются в текст, чтобы сервер не отклонил всё сообщение.

[^edits]: Hermes редактирует последний идентификатор сообщения цепочки, а SDK TrueConf не предоставляет API удаления сообщений. Поэтому при сокращении ранее разбитого ответа старые части могут оставаться на экране. Это принятое ограничение механизма редактирования.

[^voice]: Распознавание речи выполняет Hermes, а не сам плагин TrueConf. Чтобы использовать локальный `faster-whisper`, задайте в корневом блоке `stt` файла `config.yaml` параметры `enabled: true` и `provider: local`. Для русской речи можно указать `language: ru`. Библиотека `faster-whisper` должна быть доступна в окружении Hermes. После изменения настроек перезапустите шлюз.
